Query
- ORDER BY: remove the 2-column cap in QuerySorter (throws if ticket.OrderBy.Count > 2); refactor
  the SortedDictionary approach to support N sort columns, e.g. build a composite key string or
  use IComparer<List<ColumnValue>>.
- FORCE INDEX / USE INDEX: SQL syntax is not parsed. Add NodeType entries to the grammar,
  propagate the chosen index name through QueryTicket, and honour it in QueryExecutor's
  index-selection logic.

DDL / Schema
- AlterTable – rebuild indexes on column change: TableColumnAlterer.AlterColumnUniqueIndexes()
  and AlterColumnMultiIndexes() are empty stubs (return FluxAction.Continue without doing
  anything). When a column that participates in an index is modified or dropped the affected
  indexes must be rebuilt: drop old index entries, re-scan all rows, re-insert entries.

SQL Parser
- Case-insensitive identifiers: table and column name lookups use ordinal (case-sensitive)
  comparison throughout (dictionary keys, string.Equals calls). Normalise all user-supplied
  identifiers to lower-case at parse/ticket-creation time so "Users", "users", and "USERS"
  resolve to the same table.

ColumnValue / Types
- ColumnValue is a sealed class; high-insert workloads allocate one instance per cell.
  Evaluate converting it to a readonly struct or introducing a discriminated-union value type
  to eliminate heap allocation on the hot insert/query path.
- Add static sentinel values (ColumnValue.Null, ObjectIdValue.Empty) to avoid repeated
  `new ColumnValue(ColumnType.Null, "")` allocations scattered across the codebase.
